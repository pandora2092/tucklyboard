# Настройки статусов

В заголовке библиотеки откройте «Настройки». Раздел «Статусы закладок» относится к выбранному пространству. Владелец может добавлять статусы, менять название, цвет и порядок, выбирать один статус по умолчанию. Остальные участники видят настройки; редакторы могут назначать статусы закладкам, читатели просматривают их.

Кнопка «Изменить» открывает поля названия и цвета прямо в строке выбранного статуса. Поле названия получает фокус; кнопки сохранения и отмены находятся рядом. Нижняя форма предназначена только для создания нового статуса и сохраняет свой черновик при редактировании существующего.

Начальные статусы — «На потом» и «Просмотрено». Статус по умолчанию применяется к новым карточкам из интерфейса, загрузкам и входящим сообщениям Telegram-бота. При копировании в другое пространство применяется его статус по умолчанию. Уже существующие дубликаты сохраняют собственный статус.

Статусы доступны в карточке, фильтрах, массовых действиях и правилах умных коллекций.

Удаление выполняется с выбором замены: закладки и точные ссылки на статус в умных коллекциях переносятся за одну транзакцию. При удалении статуса по умолчанию выбранная замена становится новым значением по умолчанию. Последний статус удалить нельзя. Названия уникальны в пространстве без учёта регистра; доступно до 30 статусов.

## Миграция

Добавлена миграция `apps/api/prisma/migrations/20261115000000_custom_statuses/migration.sql`. Она создаёт определения старых статусов для существующих пространств и сохраняет значения `saved`/`done` в закладках. Ссылки на статусы защищены составным внешним ключом с пространством; назначения, изменения и удаление синхронизируются транзакционной блокировкой пространства.

Следующая миграция `20261115010000_remove_status_completion` убирает отдельный признак завершённости и старое условие готовности из правил умных коллекций. Остальные правила, определения статусов и назначения закладок сохраняются.

В локальной базе миграция применена. Для сервера сначала отправьте изменения в Git и сделайте резервную копию PostgreSQL. После получения нового кода пересоберите контейнеры:

```bash
git pull --ff-only
docker compose --env-file .env.production -f compose.production.yaml -f compose.nginx.yaml up -d --build
```

Сервис `migrate` автоматически применит новую миграцию перед запуском обновлённого API. Личные Telegram ID, токены и пароли остаются только в локальных или серверных env-файлах.
