# План: отдельные лимиты для фото и видео

Статус: запланировано. Рабочий лимит пока остаётся 20 МБ для всех файлов.

Фото: сохранить текущие 20 × 1024 × 1024 байт. Видео: целевой лимит 50 МБ (50 000 000 байт), после подготовки загрузки больших файлов. Область изменения — загрузка из Mini App; отправка файлов пользователем напрямую боту работает отдельно.

Обычный Telegram Bot API разрешает отправлять документы до 50 МБ. Приложение использует `sendDocument`, чтобы сохранять исходные байты. Источник: [Telegram Bot API — sendDocument](https://core.telegram.org/bots/api#senddocument), проверено 17 ноября 2026 года. Перед реализацией повторно проверить актуальный предел.

## Работы

- Разделить лимиты фото и видео в `packages/contracts/src/upload-limits.ts`. Клиент и сервер выбирают лимит по разрешённому MIME-типу; сервер самостоятельно проверяет формат и размер.
- Убрать полную буферизацию больших видео в RAM: выбрать передачу потоком либо ограниченные временные файлы с очисткой после успеха, ошибки и отмены. Ограничить параллельные загрузки.
- Согласовать общий предел multipart-запроса, лимит reverse proxy с запасом на поля формы и таймауты передачи в Telegram. Отдельная проверка фото должна продолжать отклонять файлы больше 20 МБ.
- Показывать разные лимиты для фото и видео, прогресс загрузки и понятные ошибки. Тексты брать из общих констант.
- Проверить поведение превью и повторной отправки видео больше 20 МБ: не полагаться на скачивание большого оригинала через облачный `getFile`; сохранять и использовать Telegram file_id.

## Критерии готовности

- Фото в текущих пределах принимается, превышение 20 МБ отклоняется и клиентом, и сервером.
- Видео больше 20 МБ и до целевого лимита загружается; превышение отклоняется до отправки в Telegram.
- Проверены точная граница размеров, неподдерживаемый или подменённый MIME-тип, отмена, сбой Telegram и несколько одновременных загрузок.
- Использование памяти ограничено, временные файлы удаляются, исходные файлы сохраняются без перекодирования.
