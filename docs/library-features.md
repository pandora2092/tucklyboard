# Библиотека: коллекции, пространства и поиск

## Что работает

1. Ссылка сохраняется сразу. Фоновый обработчик получает название, описание и автора через OpenGraph/Twitter metadata или YouTube oEmbed. Пользовательская заметка хранится отдельно, заданное вручную название не перезаписывается. Если сайт недоступен или требует входа, карточка остаётся доступной с исходной ссылкой; можно повторить получение данных из карточки.
2. YouTube watch/share/shorts/embed приводятся к одному идентификатору. Обычные URL очищаются от известных рекламных параметров; содержательные параметры сохраняются. Повторное сохранение внутри пространства возвращает существующую карточку, добавляет коллекции и теги, сохраняет прежние название и заметку. Дедупликация защищена транзакционной блокировкой и уникальным индексом. Старые дубликаты автоматически не удаляются.
3. Карточка может состоять в нескольких обычных коллекциях. Умная коллекция — сохранённые условия: тип, источник, все указанные теги, статус, период. Её состав вычисляется при чтении. Есть фильтры по источнику, типу, тегу и статусу, массовое назначение/снятие коллекций, добавление тегов, отметка просмотренного и удаление. Массовое действие ограничено 100 карточками и одним пространством.
4. Личное пространство доступно только владельцу. Для совместной работы создаётся отдельное пространство. Владелец управляет участниками и приглашениями; редактор добавляет и меняет карточки; читатель просматривает и получает медиа в свой чат. Приглашение действует 7 дней в интерфейсе (API: 1–30), до 20 вступлений, может быть отозвано. В базе хранится только хеш токена. Укажите `BOT_USERNAME` (без @) в `.env`, чтобы приглашение вело в бота и открывало Mini App с Telegram-авторизацией. Без него выдаётся обычный URL приложения, пригодный для локальной разработки или уже авторизованного открытия. Удаление участника закрывает доступ к API пространства, включая превью. Уже полученные человеком копии файлов отозвать невозможно.
5. Личные карточки и новые сообщения боту остаются в личном пространстве. В карточке есть явное копирование в другое доступное для записи пространство. Заметка переносится только при включённом флажке. Копия независима от исходной карточки, медиа использует тот же Telegram file_id.
6. Автотеги предлагаются локальным словарём русских и английских тем. Их можно принять как обычный тег либо скрыть. Фильтры и умные коллекции учитывают нескрытые предложения. Распознавания изображений, OCR и расшифровки видео пока нет.

## Поиск

«По словам» ищет в названии, заметке, метаданных источника, авторе и тегах. «По смыслу» без дополнительных настроек ранжирует по словам, простым формам слов и двуязычным темам/синонимам. В интерфейсе это подписано «По темам и синонимам»: это ограниченный словарь, а не нейросетевая модель.

Для neural embeddings можно настроить собственный сервер Ollama или совместимый endpoint:

```dotenv
EMBEDDINGS_URL=http://localhost:11434/api/embed
EMBEDDINGS_MODEL=nomic-embed-text
EMBEDDINGS_API_KEY=
```

Модель должна быть заранее установлена на вашем сервере. Адаптер посылает JSON `{model, input}` и принимает Ollama `embeddings[0]` либо OpenAI-compatible `data[0].embedding`. Для последнего укажите полный URL endpoint и соответствующее имя модели; ключ при необходимости передаётся как Bearer. При указании внешнего провайдера ему отправляются запросы поиска и текст карточек (включая заметки) для индексации; URL без настройки ничего модели не отправляет.

Векторы хранятся в PostgreSQL `Float[]`. Обработчик постепенно индексирует существующие карточки; отпечаток текста и имя модели защищают поиск от устаревших векторов. Ошибка модели оставляет поиск по темам доступным. Для MVP ранжируются до 2000 последних карточек, подходящих под текущие фильтры; при росте библиотеки нужен pgvector и индекс ANN. OCR, LLM-классификация и pgvector в эту версию не входят.

## Развёртывание и данные

Обычный запуск: `npm run dev`. Метаданные обрабатываются в процессе NestJS, каждые 3 секунды, по 4 карточки. Задачи сохраняются как статусы в PostgreSQL; зависшая задача подбирается повторно через 2 минуты. `ENRICHMENT_ENABLED=false` отключает обработчик. Для нагрузки можно вынести worker в отдельный процесс; сейчас Redis не требуется.

Существующая база обновлена добавочной транзакционной миграцией `infra/sql/002-spaces-intelligence.sql`, предварительная копия сохранена локально в `/tmp/save-before-priorities.sql`. Для других существующих установок сделайте собственный backup и примените SQL один раз (не на уже обновлённой базе). На пустой базе достаточно `npm run db:push`. При запуске сервер переносит прежние карточки и коллекции в личные пространства, сохраняя связи с коллекциями и ссылки на файлы. Новые файлы продолжают храниться в Telegram; S3 используется только для чтения старых данных.

Публичный HTML и метаданные скачиваются через существующий SSRF-защищённый клиент: закрытые адреса запрещены, переходы проверяются, размер и время ответа ограничены. Доступ к содержимому закрытых аккаунтов соцсетей не добавлен.

## Проверка

`npm run check` проверяет форматирование, код и CSS, Prisma, сборку, unit-тесты и интеграцию с PostgreSQL. Интеграция создаёт и удаляет только своих временных пользователей; Telegram и метаданные подменяются, реальные сообщения не отправляются. Проверяются изоляция пространств, reader/editor/owner, приглашения и отзыв доступа, несколько коллекций, дедупликация, массовые действия, умные правила, темы/синонимы, сохранность заметок и пользовательских названий при обогащении.
