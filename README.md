# tuckly

Развёртывание на Ubuntu / FirstVDS с новой базой: [пошаговая инструкция](docs/deploy-firstvds.md). Production-конфигурация — `compose.production.yaml`; локальная разработка использует прежний `compose.yaml`.

Название продукта и связанные с ним тексты заданы в общем словаре `packages/contracts/src/brand.ts` (`BRAND` и `COPY`). Его используют интерфейс, HTML-заголовок вкладки через Vite, API, Telegram-бот, имена отправляемых файлов и User-Agent предпросмотров. Для смены отображаемого названия редактируйте `BRAND.name`; затем пересоберите проект. npm-пакеты используют пространство имён `@tuckly/*`. Имена существующей PostgreSQL-базы, Docker-ресурсов и старого S3-бакета являются идентификаторами хранения и сохраняются независимо от бренда. Telegram-имя бота и адреса приложения задаются отдельно в окружении и BotFather.

Красивое избранное в Telegram: ссылки, заметки, фото и видео. NestJS + PostgreSQL, React + Telegram WebApp SDK. Новые оригиналы хранятся в Telegram, а PostgreSQL хранит каталог и идентификаторы файлов. MinIO/S3 для новых загрузок не нужен.

## Локальный запуск

Требуются Node.js 22.13+ (ветка 22) или Node.js 24+ и Docker Compose. Из корня проекта:

```sh
npm install
npm run dev
```

Одна команда создаёт `.env` из примера, если его ещё нет, запускает PostgreSQL и ждёт готовности, генерирует Prisma Client, применяет локальную схему, собирает общие контракты и запускает API, Vite и наблюдение за контрактами. Существующий `.env` не перезаписывается. `Ctrl+C` останавливает процессы разработки; данные и контейнер PostgreSQL остаются. Остановить БД можно командой `npm run stop`.

Mini App: http://localhost:5173. API: http://localhost:3000/api/health. Без `BOT_TOKEN` работают ссылки, заметки, коллекции, теги и поиск. Для фото/видео нужен Telegram. `DEV_AUTH=true` использует тестовый Telegram ID `1`, а не ваш реальный аккаунт: для отправки в ваш чат открывайте Mini App в Telegram с `DEV_AUTH=false`.

Если PostgreSQL уже запущен вне Docker, укажите `DATABASE_URL` в `.env` и выполните `npm run dev -- --skip-infra`. Остальная подготовка выполняется автоматически. Команда разработки применяет `db push` и предназначена только для локальной БД.

Отдельные команды по-прежнему доступны: `npm run dev:api`, `npm run dev:web`, `npm run build:contracts`, `npm run db:generate`, `npm run db:push`. Перед раздельным запуском один раз соберите контракты.

## Структура и общие контракты

- `apps/mini-app/src/pages/LibraryPage.tsx` — сборка страницы из компонентов.
- `apps/mini-app/src/features/catalogue` — загрузка ленты, состояние фильтров и форма карточки.
- `apps/mini-app/src/components` — карточка, боковое меню и превью.
- `apps/mini-app/src/api` — типизированный клиент, проверка запросов и ответов, обработка ошибок.
- `apps/api/src/auth` — проверка Telegram, guard и текущий пользователь.
- `apps/api/src/catalogue` — HTTP-контроллер и сервис каталога, совместимость со старым S3.
- `apps/api/src/telegram` — обработка сообщений, работа с файлами и жизненный цикл polling.
- `apps/api/src/database` — один экземпляр Prisma и подключение/отключение БД.
- `packages/contracts` — общие Zod-схемы запросов, ответов и TypeScript-типы для обоих приложений.

Контракты собираются в ESM для Vite и CommonJS для NestJS. `npm run dev` следит за их изменениями. Приватные Telegram ID файлов не входят в публичную схему карточки. PATCH-схема не задаёт значения по умолчанию для отсутствующих полей, чтобы редактирование названия не стирало заметку или теги.

## Подключение Telegram

1. Создайте бота через BotFather и добавьте `BOT_TOKEN` в `.env`.
2. Разместите API и Mini App по HTTPS. В production задайте `NODE_ENV=production`, `DEV_AUTH=false`, `WEB_ORIGIN` и `MINI_APP_URL`. В контейнере API используйте `HTTP_HOST=0.0.0.0`.
3. Настройте кнопку меню через BotFather на URL Mini App. Раздавайте `/api` через тот же домен, что и Mini App: относительные пути используются и для API, и для превью. Vite делает это автоматически в разработке.
4. Откройте личный чат с ботом и нажмите `/start`. Бот не может первым начать переписку с пользователем.
5. Отправьте или перешлите боту фото/видео. Откройте Mini App, добавьте коллекцию и теги, нажмите «Получить в Telegram» в карточке.

Бот использует long polling; запускайте только один экземпляр poller. `BOT_POLLING=false` отключает получение обновлений, но сохраняет возможность загрузок, превью и повторной отправки через API. Если раньше был настроен webhook, отключите его перед polling. `TELEGRAM_API_ROOT` — необязательная серверная настройка для локального тестового API; в обычном запуске не задавайте её.

Не открывайте локальный dev-сервер с `DEV_AUTH=true` в интернет. ID файлов принадлежат конкретному боту: при замене бота потребуется повторное добавление медиа.

## Как теперь хранятся файлы

- **Пользователь прислал файл боту:** сохраняем `file_id`, `file_unique_id`, тип Telegram-медиа, размер и ID миниатюры. Оригинал не скачивается. Большие видео тоже можно индексировать, если Telegram доставил их боту.
- **Загрузка из Mini App:** multipart-запрос до 20 МБ проходит через память API и отправляется `sendDocument` в личный чат пользователя. Записи на диск или в S3 нет. Отправка документом сохраняет исходные байты; в каталоге остаются ID из ответа Telegram.
- **Просмотр:** маленькие миниатюры до 2 МБ запрашиваются через авторизованный API, без постоянного кеша. Токен бота, `file_id` и внутренние Telegram-ссылки не попадают в браузер. Если миниатюры нет, показывается заглушка; оригинал доступен кнопкой отправки в чат. Для небольших фото-документов допускается превью самим изображением, если известен размер до 2 МБ.
- **Получение оригинала:** API проверяет владельца карточки и вызывает `sendPhoto`, `sendVideo` или `sendDocument` с сохранённым `file_id`. Оригинал через наш сервер не проходит.
- **Удаление:** удаляется только карточка каталога. Переписка, исходные сообщения и файлы в Telegram не удаляются.

Сервис не читает нативное «Избранное»: пользователь пересылает выбранное боту. Пользовательская MTProto-сессия не требуется. PostgreSQL и небольшой сервер всё ещё нужны; передача загрузок и превью расходует трафик и оперативную память.

Стандартный Bot API ограничивает скачивание через `getFile`; большие оригиналы здесь не скачиваются. Входящий Telegram-файл уже может быть сжат пользователем при отправке «как фото»; сервис не восстанавливает исходник до сжатия. Для точного оригинала отправляйте как файл. [Telegram Bot API](https://core.telegram.org/bots/api#sending-files), [grammY: файлы](https://grammy.dev/guide/files).

## Превью ссылок

YouTube-ссылки (`watch`, `youtu.be`, `shorts`, `live`, `embed`) получают обложку без Data API и API-ключей: сначала доступное высокое разрешение, затем запасной вариант. Для других публичных сайтов извлекаются `og:image`, `twitter:image`, `image_src`, обложки JSON-LD и обнаруженные JSON oEmbed-ответы, включая относительные адреса и HTML-сущности. Для TikTok короткие ссылки раскрываются до видео; обложка читается из данных этого видео в HTML, с запасным обращением к oEmbed. Аватары авторов и логотипы издателей из JSON-LD не подставляются вместо обложки.

Превью загружается по защищённому `GET /api/items/:id/preview` только после проверки владельца. Старые ссылки получают тот же адрес автоматически при загрузке ленты — пересохранять их и менять схему БД не нужно. Лента и сохранение не ждут ответа стороннего сайта. Если картинки нет, сайт закрыт или недоступен, остаётся заглушка с доменом. Встроенный проигрыватель и скачивание видео не используются.

Сервер проверяет публичность IP-адресов и каждого перенаправления, закрепляет проверенный адрес за соединением, ограничивает время, размер ответа (HTML до 4 МБ, обложка до 6 МБ) и параллелизм. HTML и обложки не записываются на диск/S3: используется ограниченный кеш RAM до 32 МБ/128 записей, успешный результат — до 30 минут, неудачный — до минуты. Превью недоступны для ссылок во внутреннюю сеть, страниц с авторизацией, JS-only страниц без исходных метатегов и неподдерживаемых форматов картинок. Поддерживаются JPEG, PNG и WebP.

## Старые карточки S3

Поле `mediaKey` и объекты в S3 сохранены. При наличии прежних `S3_ENDPOINT`, `S3_REGION`, `S3_BUCKET`, `S3_ACCESS_KEY`, `S3_SECRET_KEY` API возвращает временную ссылку на старый файл. Удаление карточки теперь не удаляет и старый S3-объект. Для локального старого MinIO:

```sh
docker compose --profile legacy-storage up -d --build minio
```

Этот профиль собирает MinIO из исходников и не нужен для новой схемы. Существующий volume сохраняется. Автоматического переноса старых файлов нет: отправьте или перешлите оригинал боту и удалите старую карточку после проверки. Старые поля Telegram не позволяют восстановить `file_id` из одного номера сообщения через Bot API.

Для обновления существующей production-БД имеется [добавочный SQL](infra/sql/20261111_telegram_media.sql); выполните его штатным инструментом миграций после резервного копирования. Он не меняет `mediaKey`. `db push` предназначен для локальной разработки.

## API медиа

- `POST /api/items/media`: multipart `file` и JSON-строка `metadata` (`title`, `text`, `tags`, `collectionId`). Проверка авторизации выполняется до загрузки в память; формат и сигнатура проверяются до обращения к Telegram.
- `POST /api/items/:id/send`: отправить оригинал только владельцу карточки. Указание другого `chatId` в теле запроса не меняет получателя.
- `GET /api/items/:id/preview`: авторизованная выдача изображения без Telegram URL и без постоянного хранения.
- Старый `POST /api/uploads` возвращает `410 Gone`.

Как и раньше, API Mini App использует заголовок `Authorization: tma <initData>`. Введённый пользователем `file_id` не принимается: ссылки на файлы появляются только из сообщений боту или ответа на загрузку.

Для совместимости проверки типов Oxlint у API используется современное разрешение модулей Node16 с CommonJS-выводом; контракты публикуют отдельные декларации для ESM и CommonJS. В приложении не добавляется дополнительная компиляция TypeScript 7.

## Проверки

```sh
npm run build
npm test
# Требуется только PostgreSQL; Telegram подменяется локальным HTTP-сервером.
npm run test:integration
```

Полная локальная проверка, при работающем PostgreSQL с актуальной схемой: `npm run check`. Она запускает Oxlint и Stylelint, проверяет форматирование, генерирует Prisma Client, собирает контракты и приложения, запускает модульные и интеграционные тесты.

В `.github/workflows/ci.yml` настроен GitHub Actions для push и pull request: Node.js 22, отдельная PostgreSQL 17, `npm ci`, подготовка схемы и `npm run check`. Токен Telegram и внешнее S3 не требуются. Workflow начнёт выполняться после отправки проекта в GitHub; локальная проверка не является запуском GitHub Actions.

Интеграционный тест создаёт временных пользователей и очищает только свои записи. Проверяет каталог, атомарное повторное получение события, входящие фото и большие видео, загрузку исходных байтов, повторную отправку нужным методом, приватность превью, запрет доступа к чужим файлам, неверные/слишком большие загрузки, блокировку бота и удаление только записи каталога. Реальные сообщения в Telegram при тестах не отправляются. Сквозная проверка с настоящим ботом требует вашего `BOT_TOKEN` и HTTPS Mini App.

## Следующие этапы и ограничения

- Общие пространства и роли пока не реализованы; все карточки личные.
- Telegram-альбом создаёт несколько карточек. Полнотекстовый поиск, массовые действия и тёмная тема ещё не добавлены.
- Загрузки буферизуются в RAM с лимитом 20 МБ на файл. Перед публичным масштабированием нужны ограничение параллельных загрузок и частоты отправки, мониторинг, резервные копии БД и очередь повторных попыток.
- Между отправкой в Telegram и записью в PostgreSQL нет общей транзакции. При ошибке БД файл остаётся в чате; API объясняет, что его можно переслать боту. Повтор загрузки после сетевого обрыва может создать повторное сообщение.
- Собственного архива оригиналов нет: доступ зависит от Telegram и сохранности токена конкретного бота.
- У Prisma CLI 6 остаётся известное предупреждение аудита по транзитивному `deepmerge-ts`; миграция CLI на новый major требует отдельной проверки.

В настройках пространства владелец выбирает цветовую тему: шалфей, океан, лаванда, песок или роза. Цвет хранится в пространстве и виден всем участникам. При переключении меняется оформление и появляется сообщение с названием пространства; прежние карточки скрываются до загрузки новых. Перед обновлением существующей БД примените [миграцию цветов пространств](apps/api/prisma/migrations/20261116000000_space_themes/migration.sql). Она добавляет поле `theme` со значением `sage`, сохраняя существующие данные.

### Админка и доступ

Админка доступна по `/admin` на адресе Mini App. Вход выполняется через Telegram: отправьте боту `/admin` и нажмите «Открыть админку». В обычном браузере без Telegram-авторизации появится инструкция для входа. В tuckly ссылка «Админка» отображается только администраторам.

В `.env` задайте `ADMIN_TELEGRAM_IDS` — ваши числовые Telegram ID через запятую. Пустой список закрывает доступ всем. После изменения перезапустите API. Нужны также действующие `BOT_TOKEN`, `MINI_APP_URL` и работающий бот. Никогда не помещайте токен бота в клиентские переменные.

Все `/api/admin/*` проверяют подписанные Telegram Mini App `initData` и список администраторов на сервере. `DEV_AUTH` не даёт доступ в админку. Подпись действует до часа: при истечении откройте админку заново кнопкой бота. Ответы админки имеют `Cache-Control: private, no-store`.

Для существующей базы перед запуском новой версии выполните [добавочную миграцию](infra/sql/20261112_admin.sql) штатным инструментом миграций после резервного копирования. Она сохраняет неизвестные даты регистрации старых пользователей как `NULL`; новые получают текущую дату при создании. Для новой локальной базы подходит `npm run db:push`.

Обзор показывает общее число пользователей, регистрации за 7 календарных дней, активных за сегодня/7/30 дней, текущее количество карточек, коллекций и общих пространств. Список поддерживает поиск по имени, username и Telegram ID, фильтр активности и страницы по 25 пользователей. Карточка пользователя содержит текущие количества материалов по типам и дневные счётчики за 30 дней; содержимое сохранений не отдаётся в административные API.

Активность — авторизованный запрос приложения или входящее сообщение боту, включая `/start`. Дни и временные метки в админке — UTC; сегодня/7/30 включают текущий день. Счётчики запросов включают фоновые обновления и повторные обращения, поэтому не являются числом сессий или уникальных действий. Повторно доставленные сообщения также могут увеличить счётчик. Просмотр административных API и команда `/admin` не увеличивают активность. Историческая активность до миграции неизвестна; число карточек отражает текущее состояние, включая копии, без удалённых записей. В локальном режиме `DEV_AUTH` обычные запросы tuckly учитываются как активность тестового пользователя.

## Оформление tuckly

Геометрия логотипа и цветка хранится в `packages/contracts/src/brand-artwork.ts`. Приложение использует её в `BrandLogo` и `BrandMark`: логотип нарисован векторными линиями и не зависит от загрузки шрифтов. Цветок и надпись подстраиваются под тему пространства. `apps/mini-app/public/favicon.svg` — значок вкладки.

Готовые материалы лежат в `assets/branding`: `tuckly-logo.svg`, `tuckly-mark.svg`, `tuckly-bot-avatar.svg` и аватар `tuckly-bot-avatar.png` (1024 × 1024). Команда `npm run branding:export` обновляет SVG из общей геометрии. При изменении аватара экспортируйте его SVG в PNG 1024 × 1024 перед синхронизацией с Telegram.

Имя, описание, приветствие и подписи кнопок бота задаются в `packages/contracts/src/brand.ts`. Изменение приветствия требует перезапуска обновлённого API. Обновление Telegram-профиля выполняется отдельно и не отправляет сообщений пользователям:

```sh
# Только просмотр профиля и подготовленных текстов, без записи.
npm run branding:bot -- --env=.env --bot=tuckly_dev_bot

# Применить оформление выбранного бота.
npm run branding:bot -- --env=.env --bot=tuckly_dev_bot --apply

# Основной бот: адрес приложения берётся из MINI_APP_URL либо SITE_DOMAIN.
npm run branding:bot -- --env=.env.production --apply
```

Скрипт проверяет имя бота через `getMe` перед изменениями. Username берётся из `--bot` или `BOT_USERNAME` выбранного env-файла; при несовпадении с токеном запись не выполняется. Обновляются имя (с сохранением пометки DEV), аватар, краткое и полное описание, команда `/start` и кнопка «Мои находки» для открытия приложения. Токены не выводятся в лог.

## Длинная лента закладок

API возвращает порции по 40 карточек и `total` — полное число результатов с текущими фильтрами, независимо от загруженной страницы. Размер порции задаётся в `packages/contracts/src/catalogue-limits.ts`. Кнопка «Показать ещё» добавляет следующую порцию; повторная попытка после ошибки не убирает уже открытые карточки.

При сохранении, удалении и фоновом обновлении метаданных клиент повторно получает уже загруженное окно страниц, оставляя текущую ленту видимой до завершения запроса. Положение восстанавливается относительно видимой карточки; при изменении фильтров начинается новая выборка. Это сохранение места в текущем сеансе, без переноса состояния через полную перезагрузку приложения.

`VirtualItemList` использует TanStack Virtual и измеряет высоту строк сетки и списка. В DOM остаются видимые строки, запас соседних строк и строка с фокусом. Настройки запаса и оценок высоты — в `apps/mini-app/src/constants/catalogue-layout.ts`; число колонок и интервалы задаёт CSS.

Поиск по смыслу по-прежнему оценивает до 2000 последних карточек, подходящих под фильтры. При превышении лимита API возвращает `searchScopeLimit`, а интерфейс явно показывает область поиска. В этом режиме `total` — число совпадений внутри проверенной области. Обычный текстовый поиск и список не имеют такого ограничения.

В ленте можно скопировать исходный URL удержанием карточки со ссылкой: после 600 мс карточка подсвечивается, при отпускании адрес записывается в буфер и показывается уведомление. Прокрутка, движение указателя, отмена жеста и взаимодействие с кнопками отменяют удержание. Обычное нажатие открывает карточку. С клавиатуры доступно Ctrl/Cmd+C при фокусе на самой карточке. Время удержания задаётся в `constants/timing.ts`, допустимое смещение — в `constants/gestures.ts`.

## Управление коллекциями и пространствами

В настройках выбранного пространства доступны поиск по коллекциям, создание, переименование и удаление. У умной коллекции можно редактировать условия; тип уже созданной коллекции сохраняется. Неизменяемые в форме условия (например, автор `addedBy`) сохраняются при редактировании. Владелец и редакторы могут управлять коллекциями, читатели видят список без действий.

Удаление коллекции убирает только её и связи с карточками, включая прежнее поле `collectionId`. Закладки остаются в библиотеке и остальных коллекциях; при отсутствии коллекций видны во входящих. Если удалена открытая коллекция, фильтр сбрасывается ко всем закладкам. API: `PATCH /api/collections/:id` (`name` и/или `rules`), `DELETE /api/collections/:id`. Пустые изменения, неизвестные поля, недопустимые правила и повторяющееся имя в том же пространстве отклоняются.

Название текущего пространства меняет только владелец, через `PATCH /api/spaces/:id` (`name` и/или `theme`). Личное пространство можно переименовать, но удалить нельзя: оно используется для находок из бота. Остальные пространства владелец может удалить через отдельное подтверждение с вводом названия. `DELETE /api/spaces/:id` транзакционно удаляет все закладки, коллекции, статусы, приглашения и членство этого пространства, сохраняя другие пространства. Исходные сообщения и файлы в Telegram не удаляются. После удаления интерфейс переключается в личное пространство.
